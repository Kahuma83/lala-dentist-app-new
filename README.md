# Lala Dentist

Aplikasi web klinik dengan Supabase sebagai database dan autentikasi.

## Menjalankan aplikasi secara lokal

Prerequisite: Node.js dan akses ke project Supabase.

1. Pasang dependencies:

   ```powershell
   npm install
   ```

2. Salin `.env.example` menjadi `.env.local`, lalu isi:

   - `VITE_SUPABASE_URL`: Project URL dari Supabase **Project Settings → API**.
   - `VITE_SUPABASE_ANON_KEY`: publishable/anon key dari Supabase.
   - `VITE_ATTENDANCE_PORTAL_URL`: URL portal absensi untuk mengarahkan akun OB dari login utama; gunakan `https://absensi.laladentist.id`.
   - `SUPABASE_SERVICE_ROLE_KEY`: diperlukan oleh `server.js` untuk pencarian username sebelum login staf dan pembuatan akun login. Jangan beri nama `VITE_*` dan jangan masukkan ke kode browser.
   - Di Cloudflare Pages project aplikasi klinik, Pages Functions `functions/api/auth/lookup-user.js` dan `functions/api/staff.js` menyediakan pencarian username dan pembuatan akun staf. Atur `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, serta `SUPABASE_ANON_KEY` (atau `VITE_SUPABASE_ANON_KEY`) di **Settings → Variables and Secrets**; secret hanya untuk server. Endpoint staf menangani preflight browser dan hanya menerima origin `https://klinik.laladentist.id` secara default. Tambahkan origin lain melalui `STAFF_API_ALLOWED_ORIGINS` sebagai daftar origin HTTPS dipisahkan koma bila diperlukan.

   Untuk Cloudflare Pages, atur `SUPABASE_URL` sebagai variable dan `SUPABASE_SECRET_KEY` sebagai secret server-side pada **Settings → Variables and Secrets** untuk Production (dan Preview bila diperlukan). Gunakan Secret API key baru Supabase (`sb_secret_...`) untuk Pages Functions di `functions/api/`; key tersebut hanya digunakan server-side. `SUPABASE_SERVICE_ROLE_KEY` masih didukung sebagai opsi kompatibilitas untuk key legacy. Endpoint `functions/api/bookings.js` juga memverifikasi access token Supabase Auth; bila variabel `SUPABASE_ANON_KEY` tidak disetel pada Pages, ia menggunakan secret key tersebut untuk verifikasi. Jangan gunakan prefix `VITE_` pada secret apa pun.

   Chat grup dokter memakai project Supabase terpisah dari database klinik. Di Cloudflare Pages project **`absensi`** (Portal Pegawai), atur `CHAT_SUPABASE_URL` sebagai variable dan `CHAT_SUPABASE_SECRET_KEY` sebagai secret server-side; keduanya juga diisi di `.env.local` untuk pengembangan. Untuk koneksi Realtime browser, atur `VITE_CHAT_SUPABASE_URL` dan `VITE_CHAT_SUPABASE_ANON_KEY` sebagai build variables di project `absensi` dan di `.env.local`; gunakan URL dan publishable/anon key dari project `group-chat-backend`. Publishable key memang dikirim ke browser, tetapi secret key tidak boleh diberi awalan `VITE_` atau dikirim ke browser. Terapkan migration `20261021000000_create_doctor_group_chat.sql`, `20261021000001_doctor_chat_realtime_broadcast.sql`, `20261021000002_add_doctor_chat_replies.sql`, `20261021000003_add_doctor_chat_pinning.sql`, `20261021000004_broadcast_doctor_chat_deletes.sql`, dan `20261021000005_add_doctor_chat_group_subtitle.sql` melalui SQL Editor pada project `group-chat-backend` saja, bukan project klinik. Migration Realtime hanya mengirim sinyal pembaruan tanpa isi pesan ke channel publik; isi pesan tetap dimuat lewat endpoint yang memverifikasi sesi dokter. Menu Chat Grup hanya ditampilkan untuk role Dokter di Portal Pegawai. Semua dokter dapat mengedit subjudul grup; perubahan disimpan dan disiarkan ke anggota lain. Pesan dapat dibalas dari toolbar, dicari berdasarkan teks/pengirim/nama lampiran, disematkan sebagai pengumuman grup, atau dihapus oleh pengirimnya untuk semua anggota. Penghapusan pesan meminta konfirmasi dan menghapus lampiran terkait dari Storage. Avatar memprioritaskan foto staf dari bucket privat `staff-profile-photos` melalui signed URL sementara, lalu memakai avatar dokter HTTPS sebagai fallback. Stiker bawaan dipotong dari gambar asli yang disediakan dan disimpan sebagai aset lokal di `attendance-portal/public/stickers`; chat hanya menyimpan penanda teks stiker, tanpa mengunggah gambar ke Supabase Storage. Service worker Portal Pegawai menyimpan aset stiker untuk pemakaian selanjutnya/offline. Gambar kiriman dikompres ke maksimal 400 KB (GIF yang perlu dikompres menjadi gambar JPEG statis); PDF dan Word maksimal 10 MB. Tombol kamera menggunakan kamera perangkat bila tersedia.

Setelah deployment, unggah ulang logo melalui **Konfigurasi → Identitas Dokumen** dan simpan agar login staf menggunakan URL logo yang dapat dibaca semua perangkat. Pegawai mengajukan melalui Portal Pegawai; Super Admin meninjau dan memilih pengganti. Pengurangan ketidakhadiran serta upah pengganti dihitung terpisah. Upah pengganti memakai snapshot gaji pokok pegawai yang digantikan dibagi 25, dan baru menjadi earning setelah Super Admin mengonfirmasi pekerjaan selesai. Konfirmasi wajib dilakukan sebelum payroll periode tugas dikunci; sistem menolak konfirmasi bila payroll sudah disetujui/dibayar. Penugasan pengganti berbayar hanya tersedia untuk Admin Cabang/Asisten dengan jabatan sama di cabang yang sama.

   Setelah migration absensi tersebut, terapkan `20261121000000_harden_payroll_absence_and_overtime.sql` untuk menolak persetujuan ketidakhadiran pada payroll yang sudah dikunci, mempertahankan absensi yang sebelumnya dicatat dengan status sama, mencatat ketidakhadiran dokter pada semua cabang terjadwal, dan membatasi pembuatan klaim lembur ke fungsi server yang memvalidasi absensi. Kompensasi tindakan kini dicatat otomatis ketika invoice lunas, termasuk invoice tanpa saldo; sinkronisasi manual tetap tersedia untuk rekonsiliasi.

4. Di Supabase Dashboard, pastikan Realtime aktif dan policies RLS pada tabel memberikan akses yang sesuai. Perubahan Realtime hanya dikirim kepada user yang berhak membaca baris berdasarkan policies tersebut.

5. Jalankan frontend dan backend lokal:

   ```powershell
   npm run dev
   ```

   Buka aplikasi di `http://localhost:3000`. `npm run dev` juga menjalankan backend pada port `3001`.

Jika konfigurasi Supabase belum diisi, aplikasi menolak login dan tidak menggunakan akun simulasi atau data lokal. Database kosong ditampilkan sebagai kosong; aplikasi tidak mengisi data contoh otomatis. Operasi di browser selalu menggunakan anon key dan tetap tunduk pada RLS; service-role key hanya boleh digunakan di server.

Data dokter dan staf dibuat dari menu data personel. Pembuatan akun login terpisah melalui aksi **Buat Akun**, dan membutuhkan `SUPABASE_SERVICE_ROLE_KEY` yang hanya tersedia di backend serta sesi Super Admin Supabase yang valid.

## Website informasi utama

Website publik yang terpisah dari aplikasi staf berada di folder `website/`. Beranda menampilkan banner Portal Pasien sebagai latar hero utama dengan manfaat booking online, pemantauan antrean, dan informasi kunjungan. Bagian “Start Your Smile Journey” berisi artikel panduan behel yang dapat dibaca langsung dengan satu tautan opsional untuk menjadwalkan konsultasi; foto ruang klinik menjadi media pendukung. Bagian cabang mencantumkan alamat dan jam operasional empat cabang aktif serta cabang Kampus yang segera hadir. Tombol WhatsApp menghubungkan pengunjung ke admin pada nomor klinik yang ditentukan di `website/index.html`. Logo dan foto menggunakan aset lokal di `website/assets/`. Tombol “Unduh aplikasi” membuka halaman pemasangan terpisah `/patient-install.html` di hostname portal pasien. Tombol “Pasang” meminta prompt instalasi PWA native jika browser mendukung; jika tidak, halaman menampilkan petunjuk pemasangan manual. Ini bukan aplikasi Android native atau unduhan APK. Untuk membuat Cloudflare Pages project tersendiri dari repository ini, gunakan branch `main`, set **Root directory** ke `website`, dan **Build output directory** ke `.`. Tidak diperlukan build command. Tambahkan variable `SUPABASE_URL` dan `SUPABASE_ANON_KEY` pada Cloudflare Pages project website agar fungsi `functions/api/site-content.js` dapat membaca konten terbit secara aman melalui RLS. Nilai anon key memang digunakan sebagai kunci publik; jangan gunakan service-role/secret key di website. Endpoint konten di-cache di edge Cloudflare selama 5 menit dan gambar CMS melalui `functions/api/site-media.js` selama 1 tahun dengan nama file unik, sehingga kunjungan berulang ke edge yang sama tidak mengunduh ulang konten/gambar dari Supabase. Cache miss, edge baru, atau penghapusan cache tetap dapat menimbulkan egress Supabase; caching mengurangi egress, bukan menjamin nol mutlak.

Pengelolaan hero, promosi, serta artikel tersedia di **Web Admin → Kelola Website** khusus Super Admin. Terapkan migration `20261113000000_public_website_cms.sql` pada project Supabase aplikasi sebelum memakai menu tersebut. Upload gambar CMS memakai bucket publik `clinic-public-media`, yang dibuat oleh migration `20261016000004_create_clinic_public_media_storage.sql`. Pengunjung hanya dapat membaca hero, promosi yang sedang dalam periode tayang, dan artikel yang sudah terbit; draft tetap tersembunyi oleh RLS. Promosi dan artikel mendukung tanggal tayang terjadwal. Jika konten website tidak muncul setelah migration diterapkan, periksa variable Cloudflare dan deployment Pages project website.

Tombol pemasangan di website utama membuka halaman mandiri `/patient-install.html` pada hostname Portal Pasien. Halaman ini memuat manifest sebelum meminta pemasangan; prompt native muncul bila didukung browser. Safari iPhone menampilkan petunjuk **Bagikan → Tambahkan ke Layar Utama**. Setelah prompt diterima, halaman pemasangan tetap terbuka dan menampilkan konfirmasi; login tersedia melalui tautan Login terpisah.

### Konfirmasi email portal pasien

Untuk mencegah pemindai email menghabiskan token konfirmasi saat memeriksa tautan, template **Authentication → Emails → Confirm sign up** harus mengarah langsung ke portal tanpa memakai `{{ .ConfirmationURL }}`. Gunakan tautan:

```html
<a href="{{ .RedirectTo }}?token_hash={{ .TokenHash }}&amp;type=signup">Buka halaman konfirmasi email</a>
```

Pendaftaran dan kirim ulang mengarahkan ke `/patient/confirm`; pasien harus menekan **Konfirmasi email** di halaman tersebut agar token diproses. Atur Supabase Site URL ke `https://pasien.laladentist.id` dan izinkan `https://pasien.laladentist.id/**` di Redirect URLs. Instruksi callback lama `/patient/login?type=signup-confirmed` tidak berlaku untuk alur ini.
